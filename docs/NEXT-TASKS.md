## 已知问题与限制

以下是确认存在的边界或风险，不等同于已复现的运行故障；当前没有列出尚未修复的阻塞使用问题。新增协议另有配对身份、厂商软件并发和待真机确认边界，见上方与设备支持表。

| 编号 | 现状 | 后续处理边界 |
|---|---|---|
| L1：N3同型号换配对 | 没有独立unit identity，无法区分同接收器重新配对的另一台同型号N3，可能沿用旧缓存。 | 有可靠身份依据再改进；不能凭型号或一次超时伪造新身份。 |
| L2：罗技身份回退 | 支持时使用设备身份；明确不支持身份功能才回退名称。同槽位同型号重新配对在回退路径下仍无法可靠区分。 | 保留已知限制；其他设备有可靠身份时复用，不能因此宣称全部罗技设备都受限。 |
| L3：厂商软件并发 | 应用内有串行和接收器锁，不能协调厂商驱动的查询；N3报文也没有请求序号，存在串包/超时风险。 | 先补并发实测、记录可复现场景再处理；尚无本版并发故障的完整真机复现记录。 |
| L4：迁移查找范围 | 只查当前EXE旁及已知开发旧目录，不全盘寻找已移走的data；新设置优先，冲突旧文件保留，不自动合并。 | 这是数据保护边界。升级时按README放回旧data；若需更广查找或合并，另行设计，不自动覆盖。 |
| L5：强制终止导出 | 普通失败和取消会清理；强制结束写报告的进程会绕过析构，所选目录可能留下一个自有.tmp，发布前旧报告不变。 | 确认进程退出后可手动删除；不为清理而新增路径日志或扫描删除用户文件。实际强制终止边界已有测试。 |
| L6：多彩状态与配对身份 | 只在状态帧到来时更新，没有主动查询或专用常驻监听；静止时可能没有新帧。同型号重配仍缺独立unit ID。 | 首次测试移动约3秒并在添加页刷新；型号变化已隔离，同型号换配对、实体唤醒和厂家软件并发待真机。 |
| L7：V9 Pro 2 的 2.4G 模式 | 接收器 `3837:6011` 的公开通道均无电量：无标准 `0006:0020`、厂商集合 `FF07:0222` 无字段、BES `0x0b` 是自增计数器。HFP 属性可读，但只是最后一次上报的缓存值，2.4G 下可能长期不变。 | 保持未支持，不用缓存值冒充实时读数。唯一剩余动作是抓厂商软件查询流量，需先重启使 USBPcap 过滤器绑定根集线器；未取得该流量前不重复尝试。 |
| L8：HFP 电池是缓存值 | `bt_hfp` 读的是 Windows 保存的最近一次 `AT+BIEV` 上报，不含充电状态；设备断开后该值仍保留。 | 显示时按"最后已知"处理，不标注为实时；出现标准 BLE `180F/2A19` 的设备仍优先走 BAS。 |

## 后续维护方式

- 先处理用户实际遇到的问题，再按可用硬件补V类验证；I/F类只在用户选择后开发，不把候选功能当成已批准需求。
- 完成验证时记录程序版本/哈希、型号、连接方式、实际步骤与结果，并链接到VALIDATION；完成适配时再更新README支持表。一个设备成功不能勾选整个协议家族。
- 确认的产品限制、可复现故障、资料推断和未测场景分别记录；没有完整证据的项目保持未完成。
- 原始身份、报文和本机路径留在被忽略的validation，公开只保留必要结论。诊断导出也须先检查隐私内容；日常运行不因此新增日志或后台采样。
